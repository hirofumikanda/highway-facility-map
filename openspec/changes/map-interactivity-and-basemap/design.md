## Context

現行の`site/main.js`・`site/style/map-style.js`は、MapLibre GL JS上に路線用・地点用PMTiles（`pipeline/tilegen/build_lines.sh`・`build_points.sh`が生成）のみを描画しており、背景地図・URL状態同期・クリックインタラクションを持たない。タイル生成パイプライン（`pipeline/preprocess/`・`pipeline/tilegen/`）は、供用終了年による現況絞り込みなど高速道路データ固有の前処理を前提に構築されている。今回追加する`geojson/N03-20260101_prefecture.geojson`（都道府県境界、123,025地物）は時系列データではなく、現況絞り込みの前処理は不要。

## Goals / Non-Goals

**Goals:**
- ナビゲーションコントロール・URLハッシュ同期・地点クリックポップアップという3つの操作性向上を、MapLibre GL JSの標準機能で実現する
- 都道府県境界をズーム4〜8のPMTiles背景レイヤーとして追加し、既存の路線・地点タイル生成パイプラインと同じ運用（`pipeline/build.sh`一括実行、`site/tiles/`への静的配置）に組み込む
- 路線配色をオレンジ系から緑系統に変更する

**Non-Goals:**
- 道路・建物・地名ラベルなど都道府県境界以外の背景地図要素は追加しない（既存要件を維持）
- 路線・背景レイヤーへのクリックポップアップは対象外（地点レイヤーのみ）
- 都道府県境界データに対する現況絞り込み等の時系列前処理は行わない（対象外のデータ特性のため不要）

## Decisions

### 1. URLハッシュ同期はMapLibreの`hash`オプションを使う
MapLibre GL JSの`Map`コンストラクタには組み込みの`hash: true`オプションがあり、ズーム・中心緯度経度・回転・傾きをURLハッシュに自動同期し、ハッシュ付きURLからの初期化にも対応する。自前でハッシュのパース・同期処理を実装する代替案もあるが、標準機能で要件（ズーム・中心緯度経度の同期）を満たせるため採用しない。

### 2. ナビゲーションコントロールは標準の`NavigationControl`を`top-right`に追加
`map.addControl(new NavigationControl(), "top-right")`で要件を満たす。カスタムUIは不要。

### 3. 地点クリックポップアップは`points`レイヤーのみを対象にした`click`イベント
`map.on("click", "points", handler)`でレイヤーを指定してリッスンし、地点マーカー以外のクリックでは発火しないようにする（背景・路線レイヤーは対象外のため誤ってポップアップが出ない）。ポップアップの内容はDOM APIで組み立て、地物のプロパティ文字列をテキストノードとして挿入する（`innerHTML`への直接埋め込みは行わない）。表示項目は地点名（`point_name`）と、`point_type`コードを人が読める種別名（ジャンクション／一般インターチェンジ／スマートインターチェンジ／その他）に変換したラベルとする。`maplibregl.Popup`はデフォルトで地図上の他の場所をクリックすると閉じる（`closeOnClick`既定値）ため、「地点以外をクリックした場合に閉じる」要件は追加実装なしで満たされる。

### 4. 都道府県境界PMTilesは既存の`pipeline/preprocess/`を経由せず`pipeline/tilegen/`に新規スクリプトを追加
路線・地点の前処理（`filter_lines.py`・`filter_points.py`）は供用終了年による現況絞り込みが目的だが、都道府県境界データにはその概念がないため前処理は不要。`geojson/N03-20260101_prefecture.geojson`を直接入力として、`build_lines.sh`・`build_points.sh`と対になる`build_prefectures.sh`をtippecanoeで実行する。

- ズーム範囲: `--minimum-zoom=4 --maximum-zoom=8`
- レイヤー名: `prefectures`
- 属性: 元データの`N03_002`〜`N03_005`は本データセットでは常にnullで背景レイヤーの描画にも使わないため、tippecanoeの`--include=N03_001 --include=N03_007`で都道府県名・都道府県コードのみを保持し、タイルサイズを抑える
- ポリゴン簡略化・結合: 123,025地物は都道府県境界の細かい断片を多数含み、低ズーム（4〜8）でそのまま出力すると不要に大きい・重いタイルになるため、`--coalesce`と`--detect-shared-borders`を指定して隣接ポリゴンを統合し、tippecanoeの標準簡略化に任せる（路線データと同様の方針、design.md旧決定4を踏襲）

`build.sh`・`deploy.sh`・`verify_tiles.py`は、路線・地点と同様に都道府県境界を扱うよう拡張する。

### 5. 都道府県境界の背景レイヤースタイルは地理院地図の白地図を参考にした固定色
地理院地図の白地図（淡い単色塗り・控えめな行政界線・注記なし）を参考に、以下を採用する（具体的な色は視覚的な参考であり、実装後の見た目確認で微調整可能）:
- 塗り: `#f5f5f2`（淡いオフホワイト）
- 行政界線: `#c9c5bb`、幅はズーム4で0.5px程度からズーム8で1px程度まで緩やかに増加
- ラベルレイヤーは追加しない（要件通り）

`map-style.js`の`layers`配列で、都道府県境界の塗り・境界線レイヤーを`lines-casing`より前（＝下）に配置し、背景レイヤーとして描画されるようにする。

### 6. 路線配色は緑系統に変更し、路線種別区分ごとの濃淡構造は維持
既存の`CASING_COLOR`・`FILL_COLOR`（`route_category`によるmatch式）・ラベル文字色（`route-labels`の`text-color`）を、現行のオレンジ系トーンから緑系統のトーンに置き換える。路線種別区分に応じて「高速自動車国道系統は濃く・指定都市高速道路等はやや控えめ」という既存の濃淡構造（design.md旧決定7）はそのまま維持し、色相のみを変更する。線幅ロジック（`ROUTE_CATEGORY_WIDTH_MULTIPLIER`・ズーム連動）は変更しない。

## Risks / Trade-offs

- [123,025地物の都道府県境界データがz4-8でも大きい/生成が遅い] → `--coalesce`・`--detect-shared-borders`・属性の絞り込み（`--include`）で緩和する。それでも実用上問題になる場合は、後続の変更でズーム帯ごとの追加間引きを検討する（本変更のスコープ外）
- [緑系統の具体的な色味は主観的な判断] → design.mdに採用色を明記し、実装後にブラウザで目視確認して調整する運用とする（既存の路線・地点配色決定と同様の進め方）
- [地点クリックのポップアップ内容が地物プロパティ全体ではなく`point_name`・`point_type`ラベルに限定される] → 現行タイルが保持する属性がこの2つのみ（design.md旧決定、`highway-tile-pipeline`要件「路線地物の属性保持」参照の対となる地点側属性）であり、表示可能な属性はこの範囲に留まる

## Migration Plan

新規静的ファイル（`prefectures.pmtiles`）の追加とスタイル・スクリプトの更新のみで、既存データやAPIへの破壊的なマイグレーションは発生しない。デプロイは既存の`pipeline/build.sh`実行→`site/`の静的配信という手順を踏襲する。ロールバックは、変更前のコミットに戻し再デプロイするだけで良い。
